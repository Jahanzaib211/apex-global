# Dev cheat-sheet — fast copy-paste

Run these in repo root (`/home/jahanzaib/Desktop/APEX GLOBAL`).

## 1. Local dev (hot reload)

```bash
pnpm dev
```

- Web site: http://localhost:4300 (change port in `.env` if busy).
- Console (staff): http://localhost:4301 — **locked behind staff login**.

> Logins for every service (console, portal, mailcow, Twenty, Chatwoot,
> Hyperswitch, nova-ops…) live in `infra/MASTER-CREDENTIALS.md` — gitignored,
> never commit or share it. The Playwright surface suite
> (`tests/e2e/surfaces/`, project `surfaces`) signs into each one and
> verifies every surface answers.

## 2. Layer checks (fastest first)

```bash
pnpm lint          # ESLint, all packages
pnpm typecheck     # tsc across packages and apps
pnpm test          # vitest: web + console + integrations + ui
```

One file at a time while hacking:

```bash
pnpm --filter @apex/web test src/lib/repo-graph.test.ts
pnpm --filter @apex/integrations test src/s3.test.ts
```

## 3. Build + restart production (PM2)

```bash
pnpm build
pm2 restart apex-global-web apex-global-console
pm2 save
```

Live site: https://tech.apexgroupcompanies.com · health on loopback first:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:4300/
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:4301/login
```

## 4. Every live surface (Playwright)

```bash
pnpm exec playwright test --project=surfaces --reporter=list
```

Probes all public tunnels + loopback apps (reachability) and signs into
console, client portal, Chatwoot, Twenty, Hyperswitch CC, nova-ops and
mailcow admin with the credentials in `infra/MASTER-CREDENTIALS.md`.
Credentials on the host, not in git — set `E2E_*` env vars to override.

Open WebUI is reachable but its admin password is not the master password;
its sign-in test is skipped unless `E2E_OPENWEBUI_PASS` is set. Hyperswitch
CC renders but cannot register the merchant yet (router build lacks
`/api/v1/auth/*` routes) — that test asserts the login form renders.

## 5. Hero / front-end UI debugging

Hero = `apps/web/src/components/hero.tsx` + CSS in `packages/ui/src/styles/base.css`.

- **Animations are pure CSS**: `hero-shimmer`, `hero-glow`, `hero-pulse`,
  `marquee-track`. Reduced-motion OS setting disables them (checked in base.css)
  — if "static", check **OS → accessibility → reduce motion** first.
- Verify animation is really running (read computed matrix values):

```bash
WEB_URL=http://localhost:4300 npx playwright test --grep "slides" --project=public-desktop
```

- No hydration: `site-header-client.tsx`, `tech-stack-marquee.tsx`,
  `repo-graph.tsx`, `lead-form.tsx`, `chat-launcher.tsx` are `"use client"`.

## 6. If the site looks wrong after an edit

```bash
rm -rf graphify-out            # regenerated by pnpm repo:graph
pnpm repo:graph                # rebuild the repo code-graph data
pnpm build && pm2 restart apex-global-web && pm2 save
```

## 7. Credentials / env

- `.env` at repo root — **never commit it**.
- Staff UI is the console, gated by login (see section 1). No debug or
  introspection endpoints are exposed on the public site, but the site does
  serve an operational API: `/api/health`, the two lead endpoints, the two
  webhook receivers and `/api/revalidate`. Every one is inventoried in
  `docs/API.md`.
- Partner integrations (Hyperswitch, Twenty, Chatwoot) store secrets
  encrypted in the DB, not in the UI. Reset via the console admin → settings.
- The single source of truth for every service login is the gitignored
  `infra/MASTER-CREDENTIALS.md`.

## 9. Deploy after change

```bash
pnpm build && pm2 restart apex-global-web && pm2 save
```

(console too: add `apex-global-console` to the restart list if it changed.)
